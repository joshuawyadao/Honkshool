# Security policy

## Supported version

Security fixes apply to the latest commit on `main`. Honkshool is currently a foundation-stage source repository and does not provide a hosted service, supported application, or release binary.

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/joshuawyadao/Honkshool/security/advisories/new) so details are not disclosed before a fix is available.

Include:

- The affected file, workflow, or future application component.
- Reproduction steps or a minimal proof of concept using synthetic data.
- The likely impact, especially for credential exposure, private-data disclosure, unsafe file operations, dependency compromise, or unintended network access.
- Any suggested remediation.

Do not include credentials, private keys, personal records, private repository content, or unredacted machine-specific paths. If private vulnerability reporting is unavailable, open a sanitized public issue that contains no exploit or sensitive details and asks for a private contact channel.

## Scope

Credential exposure, unsafe automation, dependency compromise, privacy regressions, unauthorized repository changes, and future application security failures are in scope. General support requests and feature ideas belong in regular GitHub issues.
